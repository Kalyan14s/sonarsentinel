## 1. Hypothesis
Exporting `detector/yolo11s-seg-sonar-real@0.1.0` to ONNX at a fixed 640 px input gives the same detections as PyTorch (TC-EDGE-001: every match with box IoU ≥ 0.95 and score difference ≤ 0.02) and keeps a full `sonarsentinel detect` run on CPU within NFR-02 (≤ 5 min per 1 km of survey line).

## 2. Baseline
PyTorch CPU inference of the same weights ([EXP-20260913-baseline](EXP-20260913-baseline.md)).

## 3. What changed
Runtime only: Ultralytics ONNX export (opset 18, simplified with onnxslim) executed by ONNX Runtime's CPU provider; `detection.runtime: auto` selects it (ADR-018 §10).

## 4. Setup

| Item | Value |
|---|---|
| Export | `YOLO(best.pt).export(format="onnx", imgsz=640, dynamic=False)` → `best.onnx` (38.7 MiB), 6 s |
| Parity data | `data/processed/yolo/0.1.0-real` validation split, 93 tiles (all available), conf ≥ 0.20, no SAHI |
| Matching | same class, greedy one-to-one by IoU ≥ 0.95; score tolerance 0.02 |
| NFR-02 run | `sonarsentinel detect` on `15CCT03_SSS_150528201100.xtf` (USGS Grand Bay, Klein 3900, 33 MB, the longest line on disk) with every default: ONNX detector + SAHI, PatchCore, FP filter, isotonic calibrator, chips, mosaic, JSON/CSV |
| Hardware | Intel i5-13420H (8 cores / 12 threads), 16 GB RAM, Windows 11; other development work running at the same time |
| Software | onnx 1.22.0, onnxruntime 1.30.0, onnxslim 0.1.96, ultralytics 8.4.150, torch 2.14.0+cpu |

**Commands**
```bash
python ml/export_onnx.py --model models/detector/yolo11s-seg-sonar-real/0.1.0/best.pt \
    --data data/processed/yolo/0.1.0-real --split val --images 100
sonarsentinel detect data/raw/usgs/grandbay_2015-315-FA/15CCT03_SSS_150528201100.xtf --out results/
```

## 6. Observations
- Parity is exact on this split, and ONNX Runtime is about 12% faster per tile than PyTorch on this CPU (150 vs 170 ms with the CPU idle).
- SAHI works with the ONNX model (Ultralytics loads `best.onnx` for the sliced model too).
- NFR-02 is met by extrapolating one 0.44 km line to 1 km on a laptop that was also running other work. TC-PERF-002 asks for a 1 km reference line on an 8-core CPU; the longest public line on disk is shorter, so the formal check still needs that reference line (ST-112).
- All 414 detections are `hidden`: the CPU-baseline detector and its calibrator (EXP-20260913-scoring) rarely give real seabed detections a high confidence. Throughput, not detection quality, is what this run measures.

## 7. Decision
- [x] **Adopt**: `best.onnx` is the default CPU runtime (`detection.runtime: auto`); PyTorch stays the fallback.
